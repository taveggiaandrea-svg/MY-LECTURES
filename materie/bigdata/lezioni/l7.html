Lesson 7 · A. Rezzani, slides and Spark scripts

How does Spark handle data that never stops arriving?

The rest of the Spark stack: Structured Streaming for live data, GraphX and GraphFrames for graphs, MLlib and its pipelines for machine learning.

Lesson 6 built Spark from the core up: partitioned data, transformations, actions, DataFrames and Spark SQL. On top of that core sit three more components: Structured Streaming for stream processing, GraphX for graph computation and MLlib for machine learning. This lesson takes them one at a time.

A table that never ends

Streaming data is data continuously generated by a source: clicks on a website, sensor readings, transactions. Such data should be processed incrementally: you cannot wait for the stream to end, because it never does.

Structured Streaming. The Spark component for scalable, high-throughput, fault-tolerant processing of live data streams. Built on the Spark SQL engine, it lets you express a streaming computation exactly as you would express a batch computation on static data; the engine runs it incrementally and continuously, updating the final result as new data arrive.

The trick, in the Spark documentation that the lecture shows, is to treat the stream as an unbounded input table: every new piece of data is a new row appended to it. A query on that table produces a result table, and at every trigger (a moment when Spark checks for new data) the result table is updated and written out. The documentation's example counts words in lines of text.

A stream is a table that keeps growing, and the query is written once. At time 3 the engine does not restart from scratch: it combines the new lines with the counts it already has.

The course notebook does the same on about 50 JSON files of events, each with a time and an action ("Open" or "Close"). First it counts the actions in one-hour windows with a normal, static query; then it replays the files as a stream, one file per trigger, with the same query:

streamingInputDF = (spark.readStream.schema(jsonSchema)
    .option("maxFilesPerTrigger", 1).json(inputPath))
streamingCountsDF = (streamingInputDF
    .groupBy(streamingInputDF.action, window(streamingInputDF.time, "1 hour"))
    .count())
query = (streamingCountsDF.writeStream.format("memory")
    .queryName("counts").outputMode("complete").start())

The only change from the static version is readStream in place of read. window(time, "1 hour") groups the events by the hour in which they happened; the sink is an in-memory table called counts, for testing, and outputMode("complete") keeps all the counts in it. Querying counts with SQL a few seconds apart shows the numbers growing as files are read.

When the relationships are the data

Some data are about connections: who is friends with whom in a social network, which web page links to which, which user bought which item. The natural structure is a graph, made of nodes (the entities, also called vertices) and relationships (the connections, also called edges).

Property graph. A graph whose nodes can hold any number of attributes (key/value pairs called properties) and can be tagged with labels for their roles, and whose relationships are directed, named and semantically relevant: each has a direction, a type, a start node and an end node.

GraphX is the Spark component for graphs and graph-parallel computation. It extends the RDD with a Graph abstraction: a directed multigraph (two vertices may be linked by more than one edge) with properties attached to each vertex and edge. It also includes a collection of graph algorithms and builders; the built-in algorithms named in the lecture are PageRank, which identifies important vertices from their connections, connected components, which finds the groups of vertices linked to each other, and triangle count, the number of triangles passing through each vertex.

GraphFrames is a library that simplifies the GraphX API and lets you use DataFrames instead of RDDs: a graph is a vertex DataFrame, with a column named id, plus an edge DataFrame, with columns src and dst. The course notebook builds a small social graph with it.

The notebook then asks the graph four kinds of questions. The degree of a vertex is the number of its edges, split into in-degree (edges arriving) and out-degree (edges leaving). Because vertices and edges are DataFrames, ordinary queries also work: the youngest person is 29 (David), and four edges are of type "follow". A subgraph keeps only some edges and vertices: the notebook keeps the "friend" edges between people older than 30, then drops the vertices left without edges.

A graph algorithm answers a question about structure that no single row could answer. Gabby's isolation, or the triangle among Alice, David and Esther, only appear when you follow the edges.

Machine learning on DataFrames

MLlib is Spark's machine learning library; its goal is to make practical machine learning scalable and easy. It provides learning algorithms (classification, regression, clustering, collaborative filtering), featurization (feature extraction, transformation, dimensionality reduction and selection), pipelines to build, evaluate and tune machine learning workflows, and utilities such as linear algebra and statistics.

The typical machine learning process, as the lecture describes it, starts by understanding the data and splitting them into a training set and a test set. Then the data are prepared: cleansed, and adapted to the algorithm, for example normalized or with categorical variables converted to numbers. The algorithm is trained on the training set, and the model is tested on the test set, data it has never seen.

FamilyAlgorithms in Spark ML, as listed in the lecture
Regressionlinear, generalized linear, decision tree, random forest, gradient-boosted tree, survival, isotonic
Classificationlogistic regression, decision tree, random forest, gradient-boosted tree, multilayer perceptron, linear support vector machine, one-vs-rest, naive Bayes
Clustering and other unsupervisedk-means, latent Dirichlet allocation (LDA), bisecting k-means, Gaussian mixture model
Recommendationalternating least squares (ALS); also FP-Growth and PrefixSpan, which find frequent patterns

The ML Pipeline API standardizes these pieces so they can be assembled like a production line, and the data set flowing through it is simply a DataFrame. A pipeline has three kinds of components.

Transformer, estimator, evaluator. A transformer turns a DataFrame into another DataFrame, usually by adding a column (Tokenizer, Binarizer, OneHotEncoder). An estimator is a learning algorithm: it fits a model on a DataFrame and produces a transformer, the model, that can calculate predictions for any DataFrame. An evaluator takes a DataFrame of predictions and computes metrics of how good the model is.

The slide calls the evaluator a transformer; in Spark's API it is a component of its own, which reads a DataFrame and returns a number rather than a new DataFrame.

The course's first example classifies toy sentences as being about baking (label 1) or about travel (label 0). The training set has four sentences: "sugar flour eggs" and "flour yeast salt" with label 1, "mountain trip" and "sea beach" with label 0. The pipeline has three stages.

Tokenizer lowercases each sentence and splits it on spaces into words. HashingTF turns the words into a vector of 1,000 numbers: each word is sent by a hash function (a fixed scrambling of its letters into a number) to one of 1,000 positions, which counts how many times it occurs. LogisticRegression, run for at most 10 iterations with a small penalty on large weights (regParam 0.01), learns one weight per position.

To read the predictions, recall how logistic regression decides: it adds the weights of the words in the sentence to a constant, the intercept, and turns this score \(z\) into a probability with the logistic function \(p = 1/(1+e^{-z})\); a probability above 0.5 predicts label 1. Running the course's script (we used Spark 3.5) gives an intercept of −1.14 and these weights: +2.28 for flour, which appears in both baking sentences, +1.52 for sugar, eggs, yeast and salt, −1.52 for mountain, trip, sea and beach, and 0 for the positions that no training word reaches. A test word gets the weight of the position it is hashed to.

A pipeline packs the preparation and the model together, so the test data go through exactly the steps the training data went through. The second example of the course is a linear regression that predicts the 2015 median house price of US cities from their 2014 population: a VectorAssembler (a transformer) packs the population into a features column, LinearRegression fits the model, and a RegressionEvaluator measures its error. The course materials also include a decision tree for fraud detection and notebooks on MLflow and generative AI, which the slides do not cover.

Test yourself

If only one thing from this lesson stays with you: streams, graphs and machine learning in Spark can all be seen as tables: an input table that keeps growing, a table of vertices and one of edges in GraphFrames, a DataFrame that gains a column at each pipeline stage.
