Il percorso in una mappa

La prima parte del corso segue una sola domanda: dove stanno i dati di un'azienda, e come si interrogano quando diventano troppi o troppo vari per un database classico?

Il filo: il database operativo registra, il data warehouse integra per decidere, SQL interroga; quando i dati superano una macchina si distribuiscono (NoSQL, HDFS) e si elaborano in parallelo (MapReduce, poi Spark); i dati grezzi finiscono nel data lake, accanto al warehouse.

Una query si scrive in un ordine e si legge, logicamente, in un altro. Tenere a mente l'ordine logico (un riepilogo aggiunto qui) spiega quasi tutti gli errori tipici: perché WHERE non vede le aggregazioni, perché un alias di SELECT non si può usare in WHERE.

Ordine logicoClausolaChe cosa fa
1FROM, JOIN ... ONprodotto cartesiano delle tabelle, filtrato dal predicato del join
2WHEREtiene le righe con condizione TRUE (non UNKNOWN)
3GROUP BYuna riga per combinazione dei valori di raggruppamento
4HAVINGtiene i gruppi; può usare le aggregazioni
5SELECT (e OVER)calcola le colonne, comprese le funzioni finestra
6ORDER BYordina il risultato

I modelli da riusare, con le tabelle Customers e Sales della lezione 2:

-- clienti con il totale venduto, anche chi non ha comprato nulla
SELECT c.customer_id, c.last_name, COALESCE(SUM(s.quantity * s.price), 0) AS total
FROM Customers c
LEFT JOIN Sales s ON s.customer_id = c.customer_id
GROUP BY c.customer_id, c.last_name
HAVING COALESCE(SUM(s.quantity * s.price), 0) < 100
ORDER BY total DESC;

-- clienti che non hanno mai comprato (anti-join)
SELECT c.* FROM Customers c
WHERE NOT EXISTS (SELECT 1 FROM Sales s WHERE s.customer_id = c.customer_id);

-- totale progressivo e media mobile su 3 righe, senza perdere il dettaglio
SELECT sales_date, quantity,
       SUM(quantity) OVER (ORDER BY sales_date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running,
       AVG(quantity) OVER (ORDER BY sales_date ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS moving_avg,
       LAG(quantity) OVER (ORDER BY sales_date) AS previous
FROM Sales;

Tre regole sui NULL: ogni confronto con NULL è UNKNOWN, quindi si usa IS NULL e mai = NULL; le aggregazioni ignorano i NULL, tranne COUNT(*); COALESCE(x, valore) li sostituisce.

# il word count in PySpark: trasformazioni pigre, poi un'azione
rdd = spark.sparkContext.textFile("testo.txt")
counts = (rdd.flatMap(lambda line: line.split())
             .map(lambda w: (w, 1))
             .reduceByKey(lambda a, b: a + b))   # shuffle: nuovo stage
counts.collect()                                  # azione: parte il calcolo
